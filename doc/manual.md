# 1 – 绪论

Animac 是 Scheme 程序语言的一个解释器实现。它支持 Scheme 的核心子集——S 表达式、作为一等公民的过程、词法作用域、列表——并在此之上提供了一等公民的计算续体（continuation）、卫生宏、自动尾调用优化、模块机制、基于虚拟机进程的多任务与进程间通信等特性。Animac 还能将一个 JavaScript 子集机械转译为 Scheme 解释执行（参见[第 10 章](#10--javascript-子集)）。

Animac 采用“编译器 + 中间语言虚拟机”的架构：源代码先经词法分析、语法分析、Alpha-renaming（通过换名消除嵌套词法作用域中同名变量的混淆，简称 ARN）、卫生宏展开、尾位置分析等阶段被解析为抽象语法树（AST），再由链接器完成模块合并与外部引用解析，最后由编译器编译为中间语言（IL）指令序列，在一台双栈式虚拟机上执行。对于用户而言，这一过程是透明的：用户只需提供源代码文件，或在交互式环境中逐条输入表达式。

Animac 是**非标准**的 Scheme。它没有 `let` 系列绑定形式（可用 `lambda` 或卫生宏模拟），不提供点对（dotted pair）与 `apply`，算术与比较运算符固定为二元，并且引入了 `while` 循环、花括号块、`break`/`continue` 等非传统特性。凡与惯常 Scheme 语义不同之处，本手册都会明确注明；[第 11 章](#11--与-r5rs-的主要差异)给出了汇总。

整个系统的所有程序都运行在预分配内存池之上，由垃圾回收器自动管理内存；解释器可以在 PC、服务器、Web 浏览器乃至资源受限的微控制器（MCU）等各类宿主环境中运行。

## 1.1 – 记号和术语

本节给出本手册通篇使用的规范性措辞、条目格式、示例记号与命名惯例。

### 1.1.1 – 错误情形与未规定行为

本手册区分三档与错误相关的表述：

| 表述 | 含义 | 举例 |
|---|---|---|
| **报错** | 触发运行时错误：虚拟机打印形如 `[Runtime] <指令或阶段>: <原因>` 的消息，并**终止出错的那个虚拟机进程**（其余进程继续运行；若出错的是唯一进程，整个程序随即结束）。 | 除零、对空表取 `car`、调用不可调用的对象、参数类型不符 |
| **结果是未规定的** | 实现不保证任何确定的结果，程序不应依赖。 | 向内建过程多传参数、参数与引数个数不符、`while` 表达式的值 |
| **实现定义** | 实现可自由选择，但本手册描述当前实现的确定行为。 | `display` 的输出格式、模块 ID 的构造、错误消息的文本（目前不含行列号） |

此外有两类不属于“报错”的情形：

- **编译期错误**（词法、语法、宏展开、链接错误）：打印到标准错误，形式为 `[Parser Error] ...`、`[Macro Error] ...` 等。命令行解释器遇到编译期错误会直接中止；交互式环境会回滚到提交前的会话状态。
- **软性失败**：许多失败情形不报错，而是以特殊值返回——例如 `get_item` 越界返回 `#undefined`、散列表查找缺失键返回 `#undefined`、队列读超时返回 `#undefined`、字符串解析数字失败返回 `#undefined`、数学函数结果为 NaN 时返回 `#null`。各条目中会注明；编写健壮程序时应检查这些返回值。

语言中**没有** `error`、`raise`、`guard` 之类的异常设施，用户代码不能主动抛出或捕获异常。

### 1.1.2 – 条目格式

第 4、5、6、8 章以条目（entry）形式给出全部句法形式与过程。每个条目的标题是它的**原型**：句法形式写出关键字与各个引数名，过程写出 `（名字 引数1 引数2 …）`。标题下方以斜体标注该条目的**类别**：

| 标注 | 含义 |
|---|---|
| *syntax* | 特殊形式：由编译器按关键字特殊处理，不遵循普通过程调用的求值规则 |
| *声明* | 编译期声明（`import`/`native`），运行时不产生代码 |
| *内建过程* | 内建变量（builtin）：预绑定在顶级作用域中的过程与运算符（[第 6 章](#6--内建变量)） |
| *库过程* | 本地库过程：经 `(native 库名)` 声明后以 `库名.过程名` 调用（[第 8 章](#8--本地库)） |

原型中的引数名暗示其应属的类型或形态（如 `lst` 应为列表、`index` 应为数值索引、`callback` 应为无参闭包、`thunk` 应为无参过程）。除特别说明外，条目中“返回……”指该表达式求值所得的值；不产生有意义的值的形式（如 `define`、`display`），注明“作为语句使用”。

### 1.1.3 – 求值示例

示例中的记号 `; ⇒` 读作“求值为”，给出其前表达式的值。例如：

```scheme
(+ 1 2)          ; ⇒ 3
(car '(a b c))   ; ⇒ a
```

示例代码块均为 Scheme 源码；需要特定模块或本地库时，示例会带上相应的 `import`/`native` 声明。

### 1.1.4 – 命名惯例

Animac 沿用 Scheme 的传统命名惯例：

- 以 `?` 结尾的名字是**谓词**：返回 `#t` 或 `#f`（如 `null?`、`list?`）；
- 以 `!` 结尾的名字表示**有副作用**的操作（如 `set!`、`set_item!`）；
- 含 `->` 的名字表示**类型转换**（惯用法；本地库中的等价物为 `String.atom_to_string`、`String.parseNumber`）；
- 多词的内建变量用下划线连接（`get_item`、`set_item!`）。

例外：本地库过程沿用 JavaScript 风格的命名（camelCase 如 `charCodeAt`，snake_case 如 `set_timeout`、`make_queue`），这是历史沿革，不遵循上述惯例。

## 1.2 – 构建

Animac 以**源代码**形式发布，使用之前需要先构建。解释器核心用 C 语言实现，除 C 标准库与数学库外不依赖任何第三方库，因此构建过程非常简单：只要具备 C 编译器（如 gcc）与 GNU make 即可。

在类 Unix 平台（Linux、macOS、WSL 等）上：

```
# 拉取仓库到本地
git clone https://github.com/bd4sur/Animac.git
cd Animac

# 构建
make
```

`make`（即 `make all`）在项目根目录生成两个可执行文件：

- `main`：命令行解释器（[§9.1](#91--命令行解释器-main)）；
- `repl`：交互式解释器（[§9.2](#92--交互式解释器-repl)）。

也可以用 `make main` 与 `make repl` 分别构建。编译选项为 `-O3 -Wall -Wextra -Iinclude`，链接数学库 `-lm`；`repl` 额外需要 readline 开发库（在 Debian/Ubuntu 上为 `libreadline-dev` 包）——如果不需要交互式环境，只构建 `main` 即可免除该依赖。

在 Windows 上，项目约定的构建方式是通过 WSL（Ubuntu）使用 gcc 与 make 进行构建；暂不提供 MSVC 等其他工具链的构建脚本。

## 1.3 – 验证构建

仓库附带的回归测试脚本可以对解释器做一次全面检查：

```
bash testall.sh
```

该脚本先执行 `make`，然后依次运行 `test/` 目录下的全部回归用例（覆盖语言核心、尾调用、续体与 `dynamic-wind`、卫生宏、eval、fork、进程间通信、散列表等），每个用例限时 30 秒。也可以用单个用例做快速冒烟测试：

```
./main test/test.scm
```

## 1.4 – 安装

Animac 不提供 `make install` 之类的安装目标。`main` 与 `repl` 都是自包含的单一可执行文件（除 C 运行时、数学库与 readline 外没有其他依赖），构建完成后复制到任何目录即可使用。

解释器运行时不依赖任何环境变量或配置文件：模块的搜索路径总是相对于被运行源文件所在的目录（base_dir，见 [§7.2](#72--模块搜索路径)），因此程序与其依赖的 `.scm` 模块作为一个目录整体存放、整体搬移即可。

`make clean` 清理全部构建产物。

## 1.5 – 嵌入宿主程序（Amalgamation）

效仿 Lua/SQLite 的单文件库形态，Animac 提供 Amalgamation 机制，便于把解释器核心嵌入到各类宿主程序（PC 软件、Web 浏览器、MCU 固件等）：

```
make amalg
```

该命令在项目根目录生成两个文件（由 `amalgamate.sh` 自动合并生成，**请勿手工编辑**）：

- `animac_core.h`：解释器核心的公开头文件（含 `extern "C"` 包装，也可以按 C++ 编译）；
- `animac_core.c`：解释器核心的全部实现，仅 `#include "animac_core.h"`。

收录范围是伞形头文件 `include/animac.h` 登记的解释器核心（基础设施、前端、运行时）；与宿主相关的内容——宿主适配（`am_host`）、本地库（`am_native_*`）、终端呈现（`am_highlight`）、REPL（`am_repl`）——不并入单文件，由集成方按需单独编译一同链接。桌面宿主侧源文件为 `src/am_host.c`、`src/am_native_*.c`、`src/am_highlight.c`（REPL 另加 `src/am_repl.c`）。

相关 make 目标（需要 GNU make ≥ 4.3 与 bash）：

| 目标 | 作用 |
|---|---|
| `make amalg` | 生成 `animac_core.h` / `animac_core.c`（源文件更新后自动重新生成） |
| `make main_amalg` / `make repl_amalg` | 用单文件形态构建可执行文件 |
| `make amalg-all` | 一次构建两者 |
| `make amalg-clean` | 清理单文件形态的全部产物 |

嵌入时，宿主通过虚函数表向解释器注入平台相关设施：内存分配例程（创建内存池时注入）、时间函数与事件回调（创建运行时时注入）、模块源码读取回调（链接时注入）。因此解释器核心本身不直接依赖宿主的 `malloc`、时钟与文件系统，可以移植到没有操作系统的裸机环境；仓库中提供了 ESP32 的宿主适配参考实现（`src/am_host_esp32.cpp`）。

# 2 – 词法约定

本章描述 Animac 源代码的词法结构。完整的形式语法见[附录 A](#附录-a--形式语法)。

## 2.1 – 标识符

标识符是**除定界符**（`( ) [ ] { } " ` ,`）、**空白字符**和**分号**之外的任意字符序列；Unicode 字符（包括汉字）是合法的标识符成分。因此以下都是合法标识符：

```scheme
+  -  *  /  ->  set!  null?  number->string  列表长度  x_1
```

词法分析按如下优先级识别一个记号：`#` 引导的字面量 → `'标识符`（符号）→ 数字 → 关键字 → 普通标识符。因此 `-3` 是数字，而单独的 `-` 是标识符（减号运算符）。

含一个点号的标识符（如 `Math.exp`、`List.reduce`）具有特殊含义：点号前缀是经 `import` 声明的模块别名或经 `native` 声明的本地库名，点号后缀是该模块/库中的名字（参见 [§5.4](#54--模块声明) 与[第 7 章](#7--模块机制)）。

## 2.2 – 空白与注释

空白字符（空格、制表符、换行）仅用于分隔记号，没有其他语义。

Animac 只有**行注释**：从分号 `;` 到行尾。没有块注释。

## 2.3 – 括号与块

圆括号 `(` `)` 与方括号 `[` `]` **完全等价**，可以按阅读习惯混用（但同一层必须配对）。

花括号 `{` ... `}` 是 `begin` 的词法糖：`{e1 e2 ...}` 等价于 `(begin e1 e2 ...)`。这常用于 `while` 循环体或多表达式分支：

```scheme
(while (<= i 100) {
  (set! sum (+ sum i))
  (set! i (+ i 1))
})
```

## 2.4 – 引号简写

| 写法 | 等价形式 | 含义 |
|---|---|---|
| `'标识符` | — | 符号字面量（词法层直接识别） |
| `'X` | `(quote X)` | 引用 |
| `` `X `` | `(quasiquote X)` | 准引用 |
| `,X` | `(unquote X)` | 解除引用 |

**不支持** `,@`（unquote-splicing）。

## 2.5 – 字面量

- **整数**：`[+-]?[0-9]+`，如 `0`、`42`、`-7`。
- **浮点**：含小数点或指数部分的数字，如 `3.14`、`-0.5`、`2e-5`、`1.5E+3`。
- **字符串**：`"..."`，不能跨行；支持的转义序列仅有 `\"`、`\\`、`\n`、`\t`、`\r`，其他反斜杠序列按原样保留（反斜杠本身也保留）。
- **布尔**：`#t`、`#f`。其后必须紧跟定界符（`#true` 不是合法的字面量）。
- **空值**：`#null`。**未定义**：`#undefined`。
- **符号**：`'标识符`。

语言中没有字符字面量类型（如 `#\a`）；“单字符”就是长度为 1 的字符串。

## 2.6 – 关键字

语言保留以下 28 个**句法关键字**（syntactic keyword）：

```
lambda  define  set!  let  begin  return  ...  _  if  and  or
cond  else  for  while  break  continue  case  do
quote  quasiquote  unquote  import  native
define-syntax  let-syntax  letrec-syntax  syntax-rules
```

其中 **`let`、`return`、`for`、`case`、`do` 五个关键字目前被保留但未实现**——把它们用在表达式首位置会导致编译失败。`else` 仅在 `cond` 中有意义；`break`、`continue` 仅在 `while` 循环体内有意义；`...`、`_` 仅供 `syntax-rules` 宏使用。

# 3 – 基本概念

本章介绍贯穿 Animac 语言的基本概念：变量与绑定、类型体系、值的外部表示、存储模型、作用域、尾调用、续体、进程与垃圾收集。

## 3.1 – 变量、句法关键字与区域

**变量**是对值的命名引用。变量在使用前应由 `define` 绑定（lambda 的引数也是绑定）；一个没有绑定的标识符不能作为变量使用（引用未绑定变量是报错，见 [§1.1.1](#111--错误情形与未规定行为)）。

**句法关键字**（[§2.6](#26--关键字)）是语言保留的名字，用于构造特殊形式与声明，不能用作变量名。

一个绑定的**区域**（region）是程序文本中该绑定可见的部分。Animac 的区域规则是词法的（[§3.5](#35--环境与词法作用域)）：

- lambda 引数与 lambda 体内由 `define` 定义的变量，其区域是整个 lambda 体；
- 模块顶层由 `define` 定义的变量，其区域是整个模块（并可经 `import` 被其他模块引用）；
- `let-syntax`/`letrec-syntax` 引入的宏，其区域是该形式的体；
- 内层区域中的同名绑定**遮蔽**（shadow）外层绑定。

**内建变量**（builtin）——即语言内建的过程与运算符（如 `+`、`car`、`display`，共 37 个，见[第 6 章](#6--内建变量)）——是预绑定在顶级作用域中的变量，全局可见、不可被重新绑定；用户变量不会与它们发生换名冲突。

## 3.2 – 类型的互不相干性

Animac 是动态类型语言：值自身携带类型信息，变量没有类型，任何变量可以持有任何类型的值。

语言中共有以下用户可见的基本类型：**number**（数字）、**string**（字符串）、**symbol**（符号）、**boolean**（布尔）、**null**（空值）、**undefined**（未定义）、**list**（列表）、**closure**（闭包，即过程）、**continuation**（续体）、**map**（散列表）。

与 RⁿRS 一样，Animac 的类型大体上互不相交：一个值至多属于一个基本类型。但有以下两处需要特别注意的**非正交性**：

1. **空列表 `'()` 与 `#null`**：空列表是列表（`list?` 为真），但谓词 `null?` 对空列表和 `#null` **都**返回真——`null?` 判定的是“空”这一概念而非类型。反过来，`#null` 不是列表（`list?` 为假）。
2. **`typeof` 是表示层的类型查询**：它对数字、布尔、符号、`#null`、`#undefined` 等立即值返回相应的类型名，但对**一切堆对象**（列表、字符串、散列表、闭包、续体）一律返回 `"handle"`（参见 [`typeof`](#typeof-v) 条目）。要区分具体的堆对象类型，应使用 `list?` 等谓词。

各类型的详细描述（字面写法、语义）见 [§3.3](#33--值的外部表示) 与[第 6 章](#6--内建变量)、[第 8 章](#8--本地库)的相关条目。

## 3.3 – 值的外部表示

值的外部表示（external representation）是它作为源码字面量的写法，以及 `display` 输出它的形式。Animac 没有读取器（内建 `read` 已废弃），外部表示仅用于书写源码和输出：

| 类型 | 字面写法 | `display` 输出 |
|---|---|---|
| 整数 | `42`、`-7` | 十进制（`42`、`-7`） |
| 浮点 | `3.14`、`2e-5` | `%g` 格式（`3.14`、`2e-05`） |
| 字符串 | `"你好"`、`"a\nb"` | 按原文输出，不带引号 |
| 符号 | `'foo` | 其字面，不带前导引号（`foo`） |
| 布尔 | `#t`、`#f` | `#t`、`#f` |
| 空值 | `#null` | `#null` |
| 未定义 | `#undefined` | `#undefined` |
| 列表 | `'(1 "a" #t)` | S 表达式风格（`(1 a #t)`） |
| 空列表 | `'()` | `()` |
| 闭包 | `(lambda (x) x)` | `#<closure:...>` |
| 续体、散列表等 | 无字面写法 | `#<...>` 形式 |

`display` 的具体输出格式属于实现定义。

## 3.4 – 存储模型与对象身份

数字、布尔、符号、`#null`、`#undefined` 是**立即值**（直接携带在变量中）；列表、字符串、散列表、闭包、续体是**堆对象**，变量中持有的是指向堆对象的引用（把柄）。两个变量引用同一个堆对象时，称它们具有相同的**身份**；内建谓词 `eq?` 判定身份（见 [§6.1](#61--等价谓词)）。

理解 Animac 的存储模型，要点如下：

- **新建对象的操作**：`cons`、`cdr`、`String.concat`、`String.slice`、准引用求值等返回**新分配**的对象，不改动原有对象；
- **原地修改的操作**：`push`、`pop`、`set_item!`、`Table.set`、`LLM.matmul` 就地改动对象本身，对象身份不变，所有引用该对象的变量都能观察到改动；
- **符号的唯一性是“宇宙级”的**：拼写相同的符号在任何上下文、任何模块、任何进程中都是同一个符号，`eq?` 恒为真；
- **字符串驻留**（实现定义）：源码中的字符串字面量在编译期按内容驻留复用（不限长度）；运行期构造的字符串，仅当长度不超过 32 个字符时驻留。因此：

```scheme
(eq? "abc" "abc")                                   ; ⇒ #t（字面量驻留）
(eq? (String.concat "ab" "c") (String.concat "a" "bc"))  ; ⇒ #t（短字符串驻留）
(define s1 (String.concat "aaaaaaaaaaaaaaaaaaaaaaaa" "aaaaaaaaaaaaaaaa"))
(define s2 (String.concat "aaaaaaaaaaaaaaaaaaaaaaaa" "aaaaaaaaaaaaaaaa"))
(eq? s1 s2)                                         ; ⇒ #f（长字符串不驻留）
(equal? s1 s2)                                      ; ⇒ #t（按内容比较）
```

  不要对字符串使用 `eq?` 判断内容相等——应使用 `equal?` 或 `String.equals`。散列表的字符串键依赖驻留机制（键长不得超过 32，见 [§8.3](#83--table散列表操作)）。

- **数字的身份依赖内部表示**：`eq?` 对数字要求内部表示完全相同，故 `(eq? 1 1.0)` 为假；数值相等应使用 `eqv?`/`==`（见 [§6.1](#61--等价谓词)）。
- **`System.fork` 深度复制**进程的整个堆：父子进程中的“同名”对象是身份不同的副本。

## 3.5 – 环境与词法作用域

Animac 采用**词法作用域**（静态作用域）：一个变量引用究竟绑定到哪个定义，完全由程序的文本结构决定，与运行时调用链无关。

```scheme
(define free 100)
(define foo (lambda () `(,free)))  ; 准引用也是词法作用域的
(define bar (lambda (free) (foo)))
(bar 200)   ; ⇒ (100)，而不是 (200)
```

绑定的区域规则如下（参见 [§3.1](#31--变量句法关键字与区域)）：

- 每个 `lambda` 引入一个新的区域，其**引数**与**函数体内由 `define` 定义的变量**同属于该区域；
- 内层区域中的同名绑定遮蔽外层绑定；
- 函数体内的 `define` 具有**提升**（hoisting）语义：同一区域内的所有 `define` 在整个 lambda 体内可见，近似于 `letrec*` 的语义，因此允许相互递归（一个过程可以引用同一区域内文本上稍后定义的过程）；
- 源文件（或一个模块）的顶层，在概念上被包装为一个匿名 lambda 的函数体（[§5.1](#51--程序)），因此“顶层变量”就是这个隐式 lambda 区域中的绑定。

闭包会捕获其定义处的环境，并在其后的整个生命周期内保持该环境中的绑定可用。

## 3.6 – 尾调用

Animac 实现**自动尾调用优化**（TCO）：当一个过程调用出现在“尾位置”时，它不占用新的调用栈空间，可以无限进行而不溢出。尾位置包括：

- lambda 函数体的最后一个表达式；
- `if` / `cond` 各分支的表达式；
- `begin`、`and`、`or` 的最后一个子表达式。

因此，标准的尾递归写法在 Animac 中可以放心使用：

```scheme
(define iter
  (lambda (n acc)
    (if (== n 0)
        acc
        (iter (- n 1) (* acc n)))))  ; 尾调用，不消耗栈
(iter 100000 1)
```

## 3.7 – 续体

`call/cc`（call-with-current-continuation 的惯用缩写）捕获**当前续体**——即“从这一点往后还要做的全部计算”——并将其作为第一等值传给一个过程。续体本身可以像单参数过程一样被调用：调用它，就是放弃当前计算、带着给定的值跳回捕获点。续体可以被保存、传递，并且可以**调用任意多次**。

```scheme
(((lambda (x) (begin (display "@") x)) (call/cc (lambda (k) k)))
 ((lambda (x) (begin (display "*") x)) (call/cc (lambda (k) k))))
; 输出 @*@**@***@**** ...（Yin-yang puzzle）
```

`dynamic-wind` 用于在“动态进出某段计算”时挂上守护过程：`(dynamic-wind before thunk after)` 会在进入 `thunk` 的动态作用域前执行 `before`，在离开（包括经续体跳入跳出）时执行 `after`。两个条目的细节见 [§6.7](#67--控制特征)。

基于 `call/cc` 可以在语言内实现协程、生成器、异常等控制结构（`test/coroutine.scm`、`test/generator.scm` 给出了实例）。

## 3.8 – 进程与异步任务

Animac 虚拟机内建一个事件循环，支持在**单个虚拟机内**运行多个**虚拟机进程**（process）。进程是调度的基本单位：每个进程拥有自己独立的堆、操作数栈与函数调用栈，由虚拟机以时间片轮转的方式抢占式调度。虚拟机进程不是操作系统线程，同一时刻只有一条中间语言指令在执行，因此单条指令内部不存在数据竞争。

- **进程分裂**：[`System.fork`](#systemfork) 将当前进程连同其堆、栈、闭包、续体**深度复制**一份，父子进程从同一位置继续执行（父进程得到子进程 PID，子进程得到 0）。
- **进程间通信**：[`System.make_queue`](#systemmake_queue-len) 创建容量固定的先进先出队列，[`System.write`](#systemwrite-qid-v-timeout_ms) 与 [`System.read`](#systemread-qid-timeout_ms) 在队列上收发任意值；队列满/空时进程会被阻塞（可设超时）。队列是虚拟机全局资源，`fork` 出的进程天然共享队列编号。
- **异步定时器**：[`System.set_timeout`](#systemset_timeout-time_ms-callback) 与 [`System.set_interval`](#systemset_interval-time_ms-callback) 注册一次性/周期性定时器，到期时由事件循环在**发起进程**的上下文中调用回调闭包。
- **进程终止**：进程执行完其代码后自行结束；[`System.exit`](#systemexit) 立即结束当前进程；[`System.kill`](#systemkill-pid) 可彻底终止指定 PID 的进程。

虚拟机内所有进程都结束（且没有未决的定时器与阻塞等待者）后，整个程序运行结束。

## 3.9 – 垃圾收集

Animac 自动管理内存。整个解释器（包括编译期与运行期）工作在一块启动时**预分配的固定大小内存池**上；池内部分为虚拟机工作区与用户堆区，边界按需动态调整。

垃圾回收采用**分进程标记-清除**与**全局标记-压缩**相结合的策略，由虚拟机在事件循环的每一轮之后择机执行。用户无需也无法手动释放内存；可以用 [`System.memstat`](#systemmemstat) 观察内存池用量，用 [`System.gc`](#systemgc) 强制对当前进程做一次回收。

内存池大小固定、不可动态扩容：桌面命令行解释器默认 256MB，交互式环境默认 16MB。在嵌入式宿主上集成时，池大小由宿主在创建解释器实例时指定。堆耗尽将导致分配失败。

# 4 – 表达式

表达式分为**基本表达式类型**（由语言内核直接定义）与**派生表达式类型**（概念上可以由基本形式定义，尽管本实现出于效率由编译器内建实现）。此外，`import`/`native` 声明与宏定义不是表达式（见[第 5 章](#5--程序结构)）。

字面量（数字、字符串、布尔、`#null`、`#undefined`、符号）是**自求值**的；变量引用取绑定的值；以句法关键字为首的列表是特殊形式；其余列表是过程调用（[§4.3](#43--过程调用)）。

## 4.1 – 基本表达式类型

### `(quote 数据)` / `'数据`

*syntax*

**引用**：抑制求值，把 `数据` 按字面变成值：

- 列表原样成为列表（其中的标识符一律变为符号）；
- 标识符与关键字变为符号；
- 数字、字符串、布尔等字面量保持原值。

```scheme
'(1 2 3)        ; ⇒ 列表 (1 2 3)
'foo            ; ⇒ 符号 'foo
'(a (b c) "s")  ; ⇒ 嵌套列表
'()             ; ⇒ 空列表
```

### `(lambda (引数...) 体1 体2 ...)`

*syntax*

创建闭包。引数表必须是一个（可以为空的）列表；体至少包含一个表达式，多个表达式依次求值，**最后一个表达式的值就是闭包的返回值**。

```scheme
(lambda (x y) (+ x y))
(lambda () (display "hi") 42)   ; ⇒ 闭包，调用后返回 42
```

限制：

- **不支持变参**：`(lambda args ...)` 是语法错误；`(lambda (a . b) ...)` 中的 `.` 没有 rest 语义，只会被当作一个普通引数名；
- 调用时传入的参数个数应与引数个数一致，否则结果是未规定的。

lambda 的体构成一个新的词法区域（[§3.5](#35--环境与词法作用域)）；体的最后一个表达式位于尾位置（[§3.6](#36--尾调用)）。

### `(if 谓词 真分支 [假分支])`

*syntax*

条件表达式。谓词的值为假（即 `#f`）时求值假分支，否则求值真分支。**假分支可以省略**；省略且谓词为假时，整个 `if` 的值是未规定的。两个分支都位于尾位置。

```scheme
(if (> x 0) "positive" "non-positive")
(if (null? lst) (display "empty"))   ; 无假分支
```

真值约定：**只有 `#f` 被视为假**，`#null`、`#undefined`、`0`、空表等一切其他值都视为真（[§6.3](#63--逻辑运算)）。

### `(set! 变量 表达式)`

*syntax*

先求值表达式，再把变量的已有绑定修改为所得的值。变量必须在当前区域内可见，否则报错。`set!` 不产生值，作为语句使用。

## 4.2 – 派生表达式类型

下列形式在概念上可以由基本形式定义（例如用宏），本实现由编译器内建实现。

### `(cond (谓词1 表达式1) (谓词2 表达式2) ... [(else 表达式n)])`

*syntax*

多分支条件。依次求值各子句的谓词，第一个为真的谓词所对应的表达式被求值，其值为整个 `cond` 的值；`else` 子句匹配任何情况。没有任何谓词为真且没有 `else` 时，`cond` 的值是未规定的。

限制：**每个子句只接受单个表达式**；需要多个表达式时用花括号（`begin`）包裹：

```scheme
(cond ((> x 0) "positive")
      ((< x 0) { (display "neg") "negative" })
      (else "zero"))
```

各分支表达式位于尾位置。

### `(begin 表达式...)` / `{ 表达式... }`

*syntax*

顺序求值各表达式，值为**最后一个表达式**的值。`(begin)` 是空操作。花括号 `{...}` 是 `begin` 的词法糖（[§2.3](#23--括号与块)）。仅最后一个表达式位于尾位置。

### `(while 谓词 体1 体2 ...)`

*syntax*

原生循环结构：先求值谓词，为假则结束循环；为真则依次求值各体表达式，然后回到谓词。这是 Animac 对传统 Scheme 的扩展。

循环体内可以使用 `break`（立即跳出最内层循环）与 `continue`（立即跳回谓词，开始下一次迭代）。注意二者以**裸符号**形式书写（不是 `(break)` 这样的调用形式），可以出现在循环体内任意嵌套位置（但不得出现在谓词中）：

```scheme
(define i 0)
(while #t {
  (set! i (+ i 1))
  (if (== i 10) break)
  (if (== (mod i 2) 0.0) continue)
  (display i)
})   ; 输出 13579
```

注意：

- **`while` 表达式的值是未规定的**，只应为其副作用而使用；
- 循环体**不是独立的词法区域**（与 JavaScript 的块作用域不同）：循环体内捕获的闭包看到的是同一个变量绑定。若在循环中注册异步回调，需手工封装一层 lambda 来保存每次迭代的值（参见 `test/sleepsort.scm` 的示例）。

### `(and 表达式...)` / `(or 表达式...)`

*syntax*

逻辑与/或，**多参数、短路求值**：

- `and` 从左到右求值，遇到假值（`#f`）立即结束；`(and)` 为 `#t`；
- `or` 从左到右求值，遇到真值立即结束；`(or)` 为 `#f`。

> **与标准 Scheme 不同**：`and`/`or` 的结果**恒为 `#t` 或 `#f`**，而不是最后一个被求值的参数本身。即 `(and 1 2)` 得到 `#t` 而非 `2`，`(or #f 3)` 得到 `#t` 而非 `3`。

最后一个子表达式位于尾位置。

### `(quasiquote 模板)` / `` `模板 ``

*syntax*

**准引用**与 `quote` 类似，但允许用**解除引用** `(unquote 表达式)`（简写 `,表达式`）在模板中嵌入需要求值的部分：

```scheme
(define a 100)
(define f (lambda () 3))
`(,a ,(f) b)    ; ⇒ (100 3 b)
```

unquote 中的表达式遵守词法作用域。特别地，`,'a` 先把符号 `'a` 还原为变量 `a` 再取其值：`` `(,'a) `` ⇒ `(100)`。

限制：**不支持 `,@`**（unquote-splicing）；列表拼接需自行用 `cons`/`push` 等构造。

## 4.3 – 过程调用

一般形式的表达式 `(运算符 参数1 ... 参数n)` 若不是特殊形式，则是**过程调用**：运算符位置与各个参数**按从左到右的顺序**依次求值，然后以各参数调用运算符位置的值。运算符位置可以是变量（包括内建变量、模块引用、本地库过程）、lambda 表达式，或任何求值为闭包/续体的表达式：

```scheme
((lambda (x) (+ x 1)) 41)        ; ⇒ 42
((if flag f g) x y)              ; 运算符位置可以是任意表达式
```

要点：

- 位于尾位置的调用自动成为尾调用（[§3.6](#36--尾调用)）；
- 内建算术与比较运算符固定为**二参数**（[§6.2.4](#624--算术运算)）；
- 参数个数与引数个数不符时，结果是未规定的；
- **没有 `apply`**。

## 4.4 – 宏

Animac 提供基于 `syntax-rules` 的**卫生宏**（hygienic macro）系统。宏在**编译期**展开（在 Alpha-renaming 之后、编译之前），展开结果会递归地再次展开（宏可以展开出宏）。宏的定义形式见 [§5.3](#53--语法定义)；本节描述 `syntax-rules` 变换器的写法。

### `(syntax-rules (字面量...) (模式 模板)...)`

*syntax*

`syntax-rules` 的第一个参数是字面量标识符列表（可为空 `()`），其后是至少一条 `(模式 模板)` 子句。宏调用依次与各子句的模式匹配，第一个匹配成功的子句的模板被实例化，替换整个宏调用：

```scheme
(define-syntax swap!
  (syntax-rules ()
    ((swap! a b)
     ((lambda (tmp) (set! a b) (set! b tmp)) a))))
```

### 模式语言

- 模式的第一个元素按惯例是宏名或 `_`（与整个宏调用形式匹配）；
- `_` 是通配符，匹配任意项且不绑定；
- 模式中除字面量、`_`、`...` 之外的标识符是**模式变量**；
- `...`（省略号）表示前一个模式元素重复零次或多次，支持 `前缀 元素 ... 后缀` 的结构与嵌套模式（如 `((a b) ...)`）。

### 模板与卫生性

- 模板中的模式变量被替换为匹配到的语法片段；`子模板 ...` 将其中的模式变量按重复次数展开（各变量重复次数必须一致）；
- 模板中引入的 lambda 引数与 `define` 名字会被**自动换名**（freshen），不会捕获宏使用处的同名变量——这就是“卫生性”。

### 限制（一期实现）

- 不支持跨模块导入/导出宏；
- 每层模式列表只允许一个 `...`，且 `...` 不能位于列表开头；不支持 `(... ...)` 转义写法；
- `quote`/`quasiquote`/`unquote` 内部不做宏展开；
- 宏调用不匹配任何子句是编译期错误（`[Macro Error] macro use did not match any clause`）。

# 5 – 程序结构

## 5.1 – 程序

一个 Animac **程序**就是一个源文件（模块）。解析时，整个文件在概念上被包装为一个匿名 lambda 的调用：

```scheme
((lambda () <文件内容>))
```

因此：

- 文件的顶层就是一个 lambda 的体：顶层可以混合书写 `define`、`import`/`native` 声明、语法定义与一般表达式；
- 顶层表达式**按书写顺序依次求值**；除最后一个表达式的值作为整个程序的值（随后被丢弃）外，中间表达式的值都被丢弃——顶层表达式只应为副作用（输出、启动进程、注册定时器等）而书写；
- 顶层由 `define` 定义的变量构成该模块的**导出**，可被其他模块经 `import` 引用（[第 7 章](#7--模块机制)）；
- 交互式环境（repl）对“自动显示最后一个顶层表达式的值”有特殊处理，见 [§9.2](#92--交互式解释器-repl)。

## 5.2 – 定义

### `(define 变量 值)`

*syntax*

在当前区域内绑定变量。`define` 本身不产生值，作为语句使用。

```scheme
(define x 100)
(define square (lambda (n) (* n n)))
```

限制：**没有过程简写定义形式**，`(define (f x) ...)` 是语法错误，必须写 `(define f (lambda (x) ...))`。

定义分两种情形：

- **顶层定义**：出现在模块顶层，构成模块的导出（[§5.1](#51--程序)）；
- **内部定义**：出现在某个 lambda 体内。内部定义具有**提升**语义——同一区域内的所有 `define` 在整个 lambda 体内可见（近似 `letrec*`），因此允许相互递归：

```scheme
(define even?
  (lambda (n)
    (if (== n 0) #t (odd? (- n 1)))))
(define odd?
  (lambda (n)
    (if (== n 0) #f (even? (- n 1)))))
```

## 5.3 – 语法定义

### `(define-syntax 名字 变换器)`

*syntax*

在当前区域（模块顶层或任一 lambda 体）内定义宏；`变换器` 目前只支持 `syntax-rules` 形式（[§4.4](#44--宏)）：

```scheme
(define-syntax mylet
  (syntax-rules ()
    ((mylet ((name val) ...) body1 body2 ...)
     ((lambda (name ...) body1 body2 ...) val ...))))

(mylet ((a "人类的本质") (b "是") (c "复读机"))
  (display a) (display b) (display c))   ; 人类的本质是复读机
```

当前实现中，宏定义对其所在的**整个** lambda 体生效（提升），与书写位置无关；但仍建议把宏定义置于使用之前，以保持可读性。宏定义在展开后被移除，运行时不存在。

### `(let-syntax ((名字 变换器)...) 体...)` / `(letrec-syntax ((名字 变换器)...) 体...)`

*syntax*

定义局部宏，仅在体内有效：

```scheme
(let-syntax ((inc! (syntax-rules ()
                     ((inc! x) (set! x (+ x 1))))))
  (inc! counter))
```

当前实现中 `letrec-syntax` 与 `let-syntax` 行为完全相同（见[附录 C](#附录-c--已知限制)）。

## 5.4 – 模块声明

### `(import 别名 "路径")`

*声明*

声明引入一个模块（源文件），并给它一个别名；之后用 `别名.名字` 引用该模块中定义的变量。路径必须是**字符串字面量**：

```scheme
(import List "list.scm")
(List.reduce '(1 2 3 4 5) + 0)   ; ⇒ 15
```

### `(native 库名)`

*声明*

声明使用一个本地库（native library）；之后用 `库名.过程名` 调用其中的过程。库名是标识符（不是字符串）：

```scheme
(native Math)
(Math.sqrt 2.0)   ; ⇒ 2
```

两个声明都是**编译期**的：它们可以出现在源文件中的任何位置（解析器统一收集处理），运行时不产生代码；按惯例应置于文件开头。模块机制与本地库的完整描述分别见[第 7 章](#7--模块机制)与[第 8 章](#8--本地库)。

# 6 – 内建变量

内建变量（builtin）是预绑定在顶级作用域中的内建过程与运算符，共 37 个，全局可见、不可重定义（[§3.1](#31--变量句法关键字与区域)）。

通用约定：

- 除特别说明者外，内建过程都是**固定元数**的普通过程；编译器不检查参数个数，多传参数的结果是未规定的；
- 参数类型不符时报错（[§1.1.1](#111--错误情形与未规定行为)）；
- `and`/`or` 是特殊形式（见 [§4.2](#and-表达式--or-表达式)），`call/cc`、`dynamic-wind` 由编译器特殊处理（见 [§6.7](#67--控制特征)），它们不是普通过程；
- 内建变量表中的 `write`、`read`、`fork` 三个名字已经废弃（见 [§6.6](#66--输入输出) 与 [§6.7](#67--控制特征)）。

## 6.1 – 等价谓词

以下谓词均为二参数，返回 `#t` 或 `#f`。三者判定强度的关系是：`eq?` 最强（恒等），`eqv?` 次之（数值等价），`equal?` 最弱（结构相等）。关于对象身份与存储模型的背景，见 [§3.4](#34--存储模型与对象身份)。

### `(eq? obj1 obj2)`

*内建过程*

恒等比较。对数字要求**内部表示完全相同**（`1` 与 `1.0` 不相等）；对堆对象（列表、字符串、闭包、散列表等）按对象身份比较（同一对象为真）；符号按字面比较（拼写相同的符号恒为同一符号）。

### `(eqv? obj1 obj2)`

*内建过程*

等价比较。两个参数都是数字时**按数值比较**（`1` 与 `1.0` 相等）；否则退化为 `eq?`。

### `(== obj1 obj2)`

*内建过程*

`eqv?` 的别名。

### `(equal? obj1 obj2)`

*内建过程*

深度结构相等比较：数字按数值；列表逐元素递归比较；字符串逐字符比较；其余按恒等。

```scheme
(equal? '(1 (2 3)) '(1 (2 3)))   ; ⇒ #t
(eqv? 1 1.0)                     ; ⇒ #t
(eq? 1 1.0)                      ; ⇒ #f
```

**没有 `!=`**；判断不等请写 `(not (== a b))`。

## 6.2 – 数值

### 6.2.1 – 数值类型与表示

数字类型在内部细分为三种表示：**无符号整数**、**有符号整数**与**浮点数**（IEEE-754 双精度），但在语言层面不做区分，统称 number。非负整数字面量按无符号整数存储，负整数按有符号整数存储，含小数点或指数的字面量按浮点数存储。

算术运算按如下规则在三种表示之间转换：`+`、`*` 在两个参数都是无符号整数时返回无符号整数，任一是有符号整数时返回有符号整数，任一是浮点时返回浮点；`-` 的结果恒为有符号整数或浮点；`/`、`mod`、`pow` 的结果恒为浮点。

谓词 [`number?`](#number-v) 判定一个值是否为数字；[`nan?`](#nan-v) 判定浮点 NaN。

### 6.2.2 – 实现限制

- 整数的有效位数比机器字长少若干位（用于类型标签），属于实现定义；
- 整数运算**不做溢出检查**：溢出时结果是未规定的；
- 浮点运算遵循 IEEE-754 双精度语义；本地数学库在结果为 NaN 时返回 `#null`（[§8.1](#81--math数学函数)）；
- 数值没有精确/非精确（exact/inexact）之分，也没有有理数、复数与数值塔。

### 6.2.3 – 数值常量语法

```
整数  ::= [+-]? [0-9]+
浮点  ::= 含小数点或 e/E 指数部分的十进制数
```

如 `0`、`42`、`-7`、`3.14`、`-0.5`、`2e-5`、`1.5E+3`。`-3` 是数字，而单独的 `-` 是标识符（[§2.5](#25--字面量)）。

### 6.2.4 – 算术运算

所有算术运算符都是**二参数**的；参数必须都是数字，否则报错。取负数须写 `(- 0 x)`（没有一元取负）。

#### `(+ a b)`

*内建过程*

返回 `a` 与 `b` 的和。

#### `(- a b)`

*内建过程*

返回 `a` 减 `b` 的差。

#### `(* a b)`

*内建过程*

返回 `a` 与 `b` 的积。

#### `(/ a b)`

*内建过程*

返回 `a` 除以 `b` 的商。**恒为浮点除法**（`(/ 7 2)` ⇒ `3.5`），结果恒为浮点数。除数为 0 时报错（`[Runtime] 除零错误`）。

#### `(mod a b)`

*内建过程*

返回 `a` 除以 `b` 的余数，底层为 C 语言的 `fmod`：**结果的符号跟随被除数（左操作数）**，且**恒返回浮点数**（即使两个参数都是整数，`(mod 5 2)` 得到 `1.0`）。

#### `(pow base exp)`

*内建过程*

返回 `base` 的 `exp` 次幂，恒为浮点数。

### 6.2.5 – 数值比较

#### `(> a b)` `(< a b)` `(>= a b)` `(<= a b)`

*内建过程*

数值大小比较，均为二参数。两个参数必须都是数字（统一按浮点比较），否则报错。返回 `#t` 或 `#f`。

### 6.2.6 – 数值的输入输出

- `display` 按十进制输出整数，按 `%g` 格式输出浮点数（实现定义，见 [§3.3](#33--值的外部表示)）；
- 数字 → 字符串：[`String.atom_to_string`](#stringatom_to_string-x)；
- 字符串 → 数字：[`String.parseNumber`](#stringparsenumber-x)（失败返回 `#undefined`）。

## 6.3 – 逻辑运算

真值约定：**只有 `#f` 是假值**；`#null`、`#undefined`、`0`、空字符串、空列表等一切其他值都为真。

### `(not v)`

*内建过程*

逻辑非（单参数）：`v` 为 `#f` 时返回 `#t`，其他任何值都返回 `#f`。注意 `(not 0)`、`(not #null)`、`(not #undefined)` 都是 `#f`。

`and` 与 `or` 是多参数、短路求值的特殊形式，结果恒为布尔值，见 [§4.2](#and-表达式--or-表达式)。

## 6.4 – 列表

列表是有序的值序列，是 Animac 的核心复合数据结构（[§3.4](#34--存储模型与对象身份)）。列表索引一律**从 0 开始**；浮点索引会先四舍五入取整。

与标准 Scheme 不同，Animac 的列表**不是由点对串成的链**，而是整体的序列容器：没有点对，`cons` 的第二参数必须是列表；`cdr` 返回拷贝的新列表；`push`/`pop`/`set_item!` 原地修改列表。

### `(car lst)`

*内建过程*

返回列表的首元素。对空列表或非列表时报错。

### `(cdr lst)`

*内建过程*

返回去掉首元素后的**新列表**（拷贝，不改动原列表）。对空列表时报错。

### `(cons elem lst)`

*内建过程*

返回一个新列表：`elem` 为首元素，后接 `lst` 的各元素。**不修改原列表**；第二参数必须是列表。

### `(get_item lst index)`

*内建过程*

返回列表中索引为 `index` 的元素（从 0 开始）。**越界时返回 `#undefined`**（不报错）。

### `(set_item! lst index value)`

*内建过程*

把列表中索引为 `index` 的元素**原地**替换为 `value`（列表身份不变）。越界时报错。不产生返回值，作为语句使用。

### `(push lst value)`

*内建过程*

把 `value` **原地**追加到列表尾部。不产生返回值，作为语句使用。

### `(pop lst)`

*内建过程*

**原地**删除并返回列表的尾元素；对空列表返回 `#undefined`。

### `(length lst)`

*内建过程*

返回列表的元素个数。对非列表时报错。

> 语言中没有 `append`、`list`、`map`、`for-each`。字面量列表用 quote 构造（`'(1 2 3)`）；`append`、`map`、`filter`、`reduce` 等常用高阶过程可以用内建设施自行实现，发行版 `test/list.scm` 给出了参考实现。

## 6.5 – 类型谓词与反射

以下谓词都是单参数的，返回 `#t` 或 `#f`。类型体系与两处非正交性的讨论见 [§3.2](#32--类型的互不相干性)。

### `(null? v)`

*内建过程*

`v` 为 `#null` **或空列表 `'()`** 时返回真。

### `(undefined? v)`

*内建过程*

`v` 为 `#undefined` 时返回真。

### `(atom? v)`

*内建过程*

`v` 不是堆对象时返回真——数字、布尔、符号、`#null`、`#undefined` 是原子。**注意**：字符串和列表都是堆对象，因此 `(atom? "s")` 与 `(atom? '(1))` 都是 `#f`。

### `(list? v)`

*内建过程*

`v` 是列表（含空列表）时返回真。

### `(number? v)`

*内建过程*

`v` 是数字（整数或浮点）时返回真。

### `(nan? v)`

*内建过程*

`v` 是浮点数且为 NaN 时返回真；对其他任何值返回 `#f`。

### `(typeof v)`

*内建过程*

返回反映 `v` 类型的**字符串**：

- 数字、布尔、符号、`#null`、`#undefined` 等立即值分别返回 `"number"`、`"boolean"`、`"symbol"`、`"null"`、`"undefined"`；
- **一切堆对象**——列表、字符串、散列表、闭包、续体——一律返回 `"handle"`（它们统一以堆把柄形式存在于操作数栈上，`typeof` 不做进一步解析）。

因此 `typeof` 主要用于区分原子类型；语言中也没有 `string?`、`symbol?`、`procedure?` 等谓词，可用 `number?`、`list?`、`atom?` 组合判断。

## 6.6 – 输入输出

### `(display v)`

*内建过程*

把 `v` 输出到宿主的标准输出，不带换行。各类型值的外部表示见 [§3.3](#33--值的外部表示)。不产生返回值，作为语句使用。

### `(newline)`

*内建过程*

输出一个换行符。不产生返回值。

> 内建变量表中的 `write` 与 `read` 已经废弃（空操作），不应使用。

## 6.7 – 控制特征

### `(call/cc thunk)`

*内建过程*（编译期特殊处理）

捕获当前续体（[§3.7](#37--续体)），并以该续体为唯一参数调用 `thunk`。续体可以像单参数过程一样被调用：`(k v)` 放弃当前计算、以 `v` 为 `call/cc` 表达式的值跳回捕获点。续体可被保存并**多次调用**。

```scheme
(call/cc (lambda (k) k))                     ; 捕获自身续体
(+ 1 (call/cc (lambda (k) (k 41))))          ; ⇒ 42（k 的调用跳回捕获点）
```

### `(dynamic-wind before thunk after)`

*内建过程*（编译期特殊处理）

在动态作用域上挂守护过程：**必须恰好三个参数**，且都必须是闭包。执行顺序为 `before`、`thunk`、`after`；整个表达式的值是 `thunk` 的返回值。当续体的调用导致控制流离开或重新进入 `thunk` 的动态作用域时，虚拟机保证：离开路径上的各个 `after`（从内到外）与进入路径上的各个 `before`（从外到内）都会被依次执行。

```scheme
(dynamic-wind
  (lambda () (display "enter "))
  (lambda () (display "body "))
  (lambda () (display "leave ")))
; 输出 enter body leave
```

> 内建变量表中另有一个 `fork`，其指令形式**已经废弃**（执行即报错）。进程分裂请使用 [`System.fork`](#systemfork)（[§8.4](#84--system系统功能)）。

# 7 – 模块机制

Animac 的模块就是一个源文件。一个源文件可以通过 `import` 声明（[§5.4](#54--模块声明)）引入其他源文件，把其中定义的变量纳入自己的命名空间使用。

## 7.1 – import 声明

```scheme
(import 别名 "路径")
```

`import` 必须恰好三个元素：关键字、别名（标识符）、路径（**字符串字面量**），否则是编译期错误。声明之后，被引入模块中定义的变量 `x` 以 `别名.x` 的形式引用：

```scheme
; list.scm 中定义了 map、reduce、filter 等
(import List "list.scm")
(List.reduce '(1 2 3 4 5) + 0)   ; ⇒ 15
```

- 别名是模块内的一个声明性名字，不占用变量绑定，也不参与换名；
- 每个模块**导出其全部顶层定义**，没有显式的导出列表；
- 同一文件被多次 import（路径解析到同一绝对路径）时只加载一份；
- 模块总数（含主模块）上限为 32；
- **不允许循环依赖**：模块间的 import 关系构成有向无环图，检测到循环时链接失败；
- `import` 与 `native` 都是编译期声明，可以出现在源文件中的任何位置（惯例置于文件开头），运行时不产生代码；
- 宏（`define-syntax`）目前**不能跨模块**导入导出。

## 7.2 – 模块搜索路径

每个解释器实例都有一个**基准工作目录**（base_dir）：

- 命令行解释器运行代码文件时，base_dir 是该文件所在的目录（绝对路径的目录部分）；
- 交互式环境中，base_dir 是启动 repl 时的终端当前工作目录。

链接器按如下规则把 `import` 的路径解析为绝对路径：

- 以 `/` 开头的路径视为绝对路径，直接读取；
- 其他路径一律与 base_dir 拼接（`<base_dir>/<路径>`，不做 `..` 解析等规范化处理）。

模块源码的读取经由宿主注入的回调完成（依赖倒置），因此模块可以来自文件系统、Flash 存储乃至网络；桌面宿主的默认实现就是读文件。

## 7.3 – 模块 ID 与链接过程

每个模块有一个全局唯一的**模块 ID**，由其绝对路径构造（实现定义）：去掉首字符 `/`；把 `/`、`\` 替换为 `.`；把空白字符替换为 `_`；删除 `:`；去掉末尾的 `.scm` 后缀。例如：

```
/home/u/lib/list.scm   ⇒  home.u.lib.list
D:\my proj\x.scm       ⇒  D.my_proj.x
```

链接器（linker）在主模块解析之后执行：

1. 从主模块出发，递归解析全部 `import` 依赖（每个被引入模块同样按“隐式顶层 lambda”包装后解析），按绝对路径去重；
2. 对模块依赖图做拓扑排序；检测到循环依赖则链接失败；
3. 按拓扑序把各模块的 AST 逐个合并为一棵全局 AST；
4. 重新做尾位置分析，再做**外部引用解析**：把 `别名.名字` 解析为被引入模块中经 Alpha-renaming 后的全限定名（形如 `模块ID.区域编号.原名`），要求**恰好唯一匹配**，否则链接失败。

链接完成后，全部 AST 对象被标记为静态（永生）对象，不再参与垃圾回收。

## 7.4 – 模块二进制格式

编译完成的模块可以转储（dump）为**平台无关**的二进制格式，也可以从该格式加载（load）：定长整数一律小端、计数类整数用 ULEB128 变长编码、浮点统一为 IEEE-754 双精度，字符串以 Unicode 码点序列存储，因而可以在 32 位与 64 位宿主之间互导。二进制模块带有魔数与版本号（当前版本 `202607`），并配套 PackBits 压缩。

这一机制目前主要用于解释器内部的自检与嵌入式宿主的预编译部署；命令行解释器总是从源码重新编译。

# 8 – 本地库

本地库（native library）是宿主以 C 语言实现的过程库，经 `(native 库名)` 声明（[§5.4](#54--模块声明)）后，以 `库名.过程名` 的形式调用。这是 Animac 的外部函数接口（FFI）机制。

桌面宿主（命令行解释器与交互式环境）注册了五个库：**Math**、**String**、**Table**、**System**、**LLM**。各库过程的参数经由虚拟机操作数栈传递；参数类型不符时报错。

## 8.1 – Math（数学函数）

通用约定：参数接受任意数字（整数自动转浮点计算）；**结果为 NaN 时返回 `#null`**。

### `(Math.PI)`

*库过程*

返回圆周率 π。

### `(Math.pow base exponent)`

*库过程*

返回 `base` 的 `exponent` 次幂。（与内建 `pow` 等价。）

### `(Math.sqrt x)`

*库过程*

返回 `x` 的平方根；`x` 为负时结果为 NaN，返回 `#null`。

### `(Math.exp x)`

*库过程*

返回 e 的 `x` 次幂。

### `(Math.log x)` `(Math.log10 x)` `(Math.log2 x)`

*库过程*

分别返回 `x` 的自然对数、常用对数、以 2 为底的对数。

### `(Math.sin x)` `(Math.cos x)` `(Math.tan x)` `(Math.atan x)`

*库过程*

三角函数与反正切，`x` 以弧度计。

### `(Math.floor x)` `(Math.ceil x)` `(Math.round x)`

*库过程*

分别返回 `x` 向下、向上、四舍五入取整的结果（仍是浮点数）。

### `(Math.to_fixed x n)`

*库过程*

把 `x` 四舍五入到 `n` 位小数并**以数字形式返回**（不是字符串）。`n` 被截断到 [0, 15]。

### `(Math.abs x)`

*库过程*

返回 `x` 的绝对值。

### `(Math.random)`

*库过程*

返回 [0, 1) 区间均匀分布的伪随机浮点数。首次调用时以宿主当前时间播种。

## 8.2 – String（字符串操作）

字符串的索引按字符（Unicode 码点）计，从 0 开始。

### `(String.length str)`

*库过程*

返回字符串的字符数。

### `(String.atom_to_string x)`

*库过程*

把原子值转换为字符串：`#t`/`#f` → `"#t"`/`"#f"`；`#null` → `"#null"`；`#undefined` → `"#undefined"`；数字按其显示格式；符号取其字面；字符串返回其副本；其他类型返回空串 `""`。

这就是 Animac 的 `number->string`。

### `(String.concat str1 str2)`

*库过程*

返回两个字符串拼接而成的新字符串。

### `(String.charCodeAt index str)`

*库过程*

返回字符串 `str` 中索引 `index` 处字符的码点（数字）。**注意 index 在前**（与 `charAt` 的参数顺序相反）。越界返回 `0.0`。

### `(String.fromCharCode charcode)`

*库过程*

返回由码点 `charcode` 构成的单字符字符串。

### `(String.slice str start end)`

*库过程*

返回 `str` 的切片 [start, end)。支持负索引（从末尾倒数）；自动截断到合法范围；`start` 超过 `end` 时按空串处理。

### `(String.charAt str index)`

*库过程*

返回 `str` 中索引 `index` 处的单字符字符串。**注意 str 在前**（与 `charCodeAt` 相反）。越界返回 `""`。

### `(String.equals str1 str2)`

*库过程*

两个字符串逐字符相等时返回 `#t`，否则 `#f`。

（对字符串也可以用 `equal?` 比较，二者等价。）

### `(String.parseNumber x)`

*库过程*

把字符串完整解析为数字并返回；空串、含残余字符或解析失败时返回 `#undefined`。

这就是 Animac 的 `string->number`。

## 8.3 – Table（散列表操作）

散列表以 **数字、符号或字符串** 为键（字符串键的长度不能超过 32 个字符——短字符串经驻留机制保证相同内容的字符串具有相同身份，见 [§3.4](#34--存储模型与对象身份)），值可以是任何类型。注意非负整数键按无符号整数归一化存储，因此 `1` 与 `1.0` 是**不同的键**。

### `(Table.make)`

*库过程*

创建并返回一个空散列表。

### `(Table.set tbl key value)`

*库过程*

把 `key` 映射到 `value`（已存在则覆盖）。**`value` 为 `#undefined` 时等价于删除该键**。返回 `#undefined`。

### `(Table.get tbl key)`

*库过程*

返回 `key` 映射的值；键不存在时返回 `#undefined`。

### `(Table.contains tbl key)`

*库过程*

表中存在 `key` 时返回 `#t`，否则 `#f`。

### `(Table.delete tbl key)`

*库过程*

删除 `key` 及其映射。返回 `#undefined`。

### `(Table.keys tbl)`

*库过程*

返回由全部键组成的列表。键的顺序是内部哈希槽顺序，不作任何保证。

### `(Table.length tbl)`

*库过程*

返回表中条目的个数。

## 8.4 – System（系统功能）

System 库提供进程管理、定时器、进程间通信、动态求值与系统信息等功能。定时器与阻塞等待的时间语义依赖宿主提供的时间函数。虚拟机进程与事件循环的概念见 [§3.8](#38--进程与异步任务)。

### 进程管理

#### `(System.exit)`

*库过程*

立即停止当前虚拟机进程（置为 STOPPED）。已注册的异步任务（定时器等）不受影响。

#### `(System.kill pid)`

*库过程*

彻底终止 PID 为 `pid` 的进程（释放其堆、栈与异步任务）。成功返回 `#t`，PID 无效时返回 `#f`。杀死自身时，终止动作延迟到调度安全点执行。

#### `(System.fork)`

*库过程*

把当前进程**深度复制**一份（堆、操作数栈、函数调用栈、闭包、续体、dynamic-wind 栈全部复制），两个进程从同一点继续执行：**父进程中返回子进程的 PID，子进程中返回 0**。

```scheme
(define pid (System.fork))
(if (== pid 0)
    (display "child")
    (display "parent"))
```

定时器不随 fork 复制；队列是虚拟机全局资源，父子进程共享队列编号（这正是 IPC 的基础）。

#### `(System.exec code)`

*库过程*

把字符串 `code` 中的源码编译为模块，**原地替换当前进程的全部内容**并从起点开始执行（“夺舍”）。失败时压栈 -1 并继续执行当前进程。

#### `(System.eval codestr)`

*库过程*

在运行期把字符串 `codestr` 编译为代码，并在**当前进程内**执行。eval 的代码可以看到当前进程的**顶级变量绑定**，但不能创建新的顶级绑定；eval 代码中可以再写 `(native ...)` 声明。eval 内部发生错误（如引用未定义变量）不影响宿主进程继续执行。不产生返回值。

```scheme
(define x 100)
(System.eval "(display x)")   ; 输出 100
```

### 定时器

#### `(System.set_timeout time_ms callback)`

*库过程*

注册一次性定时器：`time_ms` 毫秒后在**当前进程**的上下文中调用无参闭包 `callback`。返回定时器编号（大于 0）；延时无效时返回 0。

#### `(System.set_interval time_ms callback)`

*库过程*

注册周期性定时器，语义同上，到期后自动按同一间隔重新排期。

#### `(System.clear_timeout timer)` `(System.clear_interval timer)`

*库过程*

取消编号为 `timer` 的定时器（两个名字等价）。

异步回调的执行模型（参见 [§3.8](#38--进程与异步任务)）：

- 回调由事件循环在循环边界统一触发，不保证在精确的到期时刻执行；
- 回调**复用发起进程**，在其上下文中同步执行，接收零个参数；
- 回调闭包在注册时被标记为保活（keepalive），不会被垃圾回收；
- 进程被阻塞（队列等待中）时其定时器暂缓触发；进程被 `kill` 后其定时器被清除。

### 进程间通信（队列）

#### `(System.make_queue len)`

*库过程*

创建容量为 `len` 的多生产者多消费者先进先出队列，返回队列编号；失败返回 `#null`。队列是虚拟机全局资源，为所有进程共享。

#### `(System.write qid v timeout_ms)`

*库过程*

把值 `v`（任意类型）写入队列 `qid`。成功返回 `#t`；队列满时：若 `timeout_ms` 为 0，立即返回 `#f`，否则当前进程被阻塞，直到队列有空间（返回 `#t`）或超时（返回 `#f`）。

#### `(System.read qid timeout_ms)`

*库过程*

从队列 `qid` 读出一个值并返回。队列空时：若 `timeout_ms` 为 0，立即返回 `#undefined`，否则当前进程被阻塞，直到队列有值（返回该值）或超时（返回 `#undefined`）。

队列可以作为信号量/互斥锁使用（例如以容量 1 的队列模拟互斥锁），配合超时机制可以检测死锁（参见 `test/test_deadlock.scm`）。

### 系统信息与其他

#### `(System.timestamp)`

*库过程*

返回当前时间戳，单位毫秒（由宿主时间函数提供）。

#### `(System.memstat)`

*库过程*

返回四元素列表 `(vm_capacity vm_used heap_capacity heap_used)`，分别是虚拟机工作区容量/已用量、堆区容量/已用量，单位字节。

#### `(System.gc)`

*库过程*

强制对当前进程做一次垃圾回收。成功返回 `#t`。

#### `(System.test x)`

*库过程*

保留的调试函数，返回形如 `"Value=<数值>"` 的字符串。

## 8.5 – LLM（语言模型推理）

*可选特性*（依赖宿主注册该库）

LLM 库提供一个小型语言模型（Nano 架构、F32 权重）的推理支持。模型文件以 base64 编码的字符串形式传入；模型状态是**虚拟机全局单例**，为所有进程共享，重复 `init` 会先卸载旧模型。未成功 `init` 之前调用其余过程时报错。

### `(LLM.init modelFileBase64)`

*库过程*

从 base64 编码的模型文件字符串加载模型（解析模型头、词表与权重映射）。仅支持 Nano 架构、F32 精度。

### `(LLM.get_config)`

*库过程*

返回 9 元素列表，依次为模型的超参数：`(block_size vocab_size n_layer n_embd n_head n_kv_head n_hidden is_shared_classifier head_dim)`。

### `(LLM.get_param)`

*库过程*

返回 14 个权重张量（均为浮点列表），依次为：`rms_norm_attn`、`rms_norm_ffn`、`rms_norm_final`、`token_embedding`、`wq`、`wk`、`wv`、`wo`、`w1`、`w2`、`w3`、`freq_cis_real`、`freq_cis_imag`、`token_classifier`。

### `(LLM.encode text)`

*库过程*

把文本 `text` 分词，返回 token 编号组成的列表。

### `(LLM.decode token_id)`

*库过程*

把单个 token 编号还原为文本字符串。

### `(LLM.matmul xout x w xout_offset w_offset n d)`

*库过程*

矩阵乘法：`xout[xout_offset+i] = Σⱼ w[w_offset+i·n+j] · x[j]`（i 取 0 到 d-1）。**原地改写**列表 `xout` 的元素，无返回值。

借助该库，可以用 Scheme 实现完整的自回归文本生成（参见 `test/llm.scm`）。

# 9 – 独立解释器

桌面宿主提供两个可执行程序：批处理式的命令行解释器 `main` 与交互式解释器 `repl`。

## 9.1 – 命令行解释器 main

```
./main <source.scm>
```

`main` 接受恰好一个文件路径参数：

- 路径以 `.js` 结尾时，先经 JavaScript 转译器（[第 10 章](#10--javascript-子集)）转译为 Scheme 再执行；
- 其他文件（通常为 `.scm`）按 UTF-8 源码读入执行。

执行时，整个文件在概念上被包装为一个匿名 lambda 的函数体（[§5.1](#51--程序)），随后完成解析、链接（base_dir 为源文件所在目录，[§7.2](#72--模块搜索路径)）、编译，最后加载到虚拟机中运行，直至所有进程结束。

说明事项：

- 程序运行前会向 stdout 打印若干诊断行（`Module dumped: ...`、`Module compressed: ...`、`Module loaded: ...`），它们是模块转储/加载自检的输出，**不是用户程序的输出**；
- `display` 的输出与运行时错误消息都打印到 stdout；
- 正常结束时退出码为 0；未提供参数时为 1；文件不存在、解析或编译失败等致命错误会直接中止进程（无优雅的错误码）；
- 默认内存池为 256MB（[§3.9](#39--垃圾收集)），默认调度时间片为 8192 条指令；
- 无参数运行时打印 `Usage: main <source.scm>`。

## 9.2 – 交互式解释器 repl

```
./repl           ; Scheme 模式
./repl --js      ; JavaScript 模式
```

repl 提供行编辑与历史（基于 readline）。主提示符为 `> `；输入不完整（括号未配平）时进入续行，提示符为 `... ` 并按未闭合括号层数缩进。

### 特殊指令

在一行完整输入时可用：

| 指令 | 作用 |
|---|---|
| `exit` `quit` `(exit)` `(quit)` `.exit` `.quit` `(System.exit)` 或 Ctrl+C | 退出 repl |
| `.help` | 显示帮助 |
| `.reset` | 彻底重置会话（清空全部历史与上下文） |
| `.js` / `.javascript` | 切换到 JavaScript 模式（重置会话） |
| `.scm` / `.scheme` | 切换到 Scheme 模式（重置会话） |

### 重放式语义

repl 是**重放式**（replay）的：每提交一次输入，repl 把新输入追加到累积的会话（全部历史源码）之后，剥离历史中由 repl 自动插入的 `display`，然后把**整个会话从头重新编译、重新执行**。因此：

- 之前 `define` 的变量在后续输入中可用；
- 若最后一个顶层表达式不是 `define`/`set!`/`import`/`native` 或已知的副作用调用，repl 会自动打印它的值；
- **一切副作用在每次提交时都会被重放**：定时器会重新注册、`fork` 会重新发生、依赖的模块会重新读盘。编写会话时应尽量保持幂等，避免在顶层直接放置依赖物理世界的副作用代码；
- 编译或运行出错时，会话回滚到本次提交之前的状态；
- repl 中**支持 `(import 别名 "相对路径.scm")`**，base_dir 为启动 repl 时的终端当前工作目录；代价是每次提交都会重新读盘并重新链接所有依赖模块；
- 默认内存池为 16MB。

# 10 – JavaScript 子集

*可选特性*（js2scm 转译器）

Animac 可以把一个 JavaScript 子集机械转译为 Scheme 再解释执行。命令行解释器对 `.js` 文件自动启用该功能；repl 可用 `--js` 启动或 `.js` 指令切换。

转译器支持的语法：

- **字面量**：数字（含小数与科学计数法）、`"字符串"`、`true`/`false`/`null`/`undefined`（分别转译为 `#t`/`#f`/`#null`/`#undefined`）；注释 `//` 与 `/* */`；
- **声明**：`var x [= e]`（→ `define`，无初值时为 `#undefined`）、`function f(a, b) {...}`（→ `define` + `lambda`）、箭头函数 `(a, b) => {...}`；
- **语句**：`if (c) {...} [else if ... else {...}]`、`while (c) {...}`、`break`、`continue`、`return e`（注意：`return` **不是提前返回**，只是把 `e` 留在函数体末位，依赖“最后一个表达式即返回值”的语义）、块 `{...}`；
- **表达式**：赋值 `=`（→ `set!`）、下标读写 `a[i]` / `a[i] = v`（→ `get_item` / `set_item!`）、三元 `c ? t : f`、`||` `&&`、比较 `== < > <= >=`、算术 `+ - * / %`（`%` → `mod`）、`^`（→ `pow`）、一元 `! -`、前后缀 `++ --`（→ `(set! x (+/- x 1))`，前后缀语义相同）、过程调用 `f(...)`、数组字面量 `[a, b]`（→ 准引用列表）。

标识符允许字母、数字、`_`、`$`、`.`（点号用于 `Math.pow` 这类本地库引用）。整个 JS 文件被包装为一个匿名 lambda 调用。转译阶段的错误消息带有行列号。

暂不支持：对象字面量与属性访问（`.` 取属性）、数组方法、`for` 循环、`switch`、变参过程等。

# 11 – 与 R5RS 的主要差异

Animac 参考但不遵守 RⁿRS 标准。以下汇总本手册各处提到的、与 R5RS 的主要差异，便于熟悉 Scheme 的读者快速定位：

**不具备的特性**

- 没有 `let`/`let*`/`letrec`/`named let`（`let` 是保留字但未实现；可用 `lambda` 或卫生宏模拟）；
- 没有 `define` 的过程简写形式 `(define (f x) ...)`；
- 没有点对（dotted pair）与非正规列表；`cons` 的第二参数必须是列表；
- 没有变参 lambda（`(lambda args ...)` 是语法错误；`(lambda (a . b) ...)` 中的 `.` 无 rest 语义）；
- 没有 `,@`（unquote-splicing）；
- 没有 `apply`、`map`、`for-each`、`append`、`list`、`assoc` 等常用库过程（可自行实现）；
- 没有 `error` 与异常机制；
- 没有字符类型（`#\a`）、没有 `string?`/`symbol?`/`procedure?` 谓词、没有块注释；
- 没有数值塔（无有理数、复数，无精确/非精确之分）；整数运算不做溢出检查；
- 不支持跨模块导入导出宏；
- `letrec-syntax` 与 `let-syntax` 行为相同。

**语义不同的特性**

- `and`/`or` 的结果恒为 `#t`/`#f`，不返回参数本身；
- 算术与比较运算符固定为二参数；`(+ 1 2 3)` 的结果是未规定的（多余参数残留在操作数栈上）；
- `/` 恒为浮点除法；`mod` 恒返回浮点、符号跟随被除数（`fmod` 语义）；
- `cdr` 返回拷贝的新列表；`push`/`pop`/`set_item!` 原地修改列表；
- 列表支持 O(1) 随机访问（`get_item`/`set_item!`，索引从 0 开始）；
- `null?` 对 `#null` 和空列表都为真；
- `cond` 的每个子句只接受单个表达式；
- `typeof` 对一切堆对象一律返回 `"handle"`；
- 数字字面量区分整/浮由书写形式决定（有无小数点或指数），内部另分有/无符号整数；
- 过程调用的运算符位置与各参数**按从左到右**的顺序求值（RⁿRS 不规定顺序）。

**额外拥有的特性**

- `while` 循环与 `break`/`continue`；花括号 `{...}` 作为 `begin` 的词法糖；
- `import` 模块机制与 `native` 本地库声明；
- 虚拟机进程（`System.fork`）、FIFO 队列进程间通信、异步定时器；
- Math/String/Table/System/LLM 本地库；
- `#null`、`#undefined` 两个额外的原子值；
- JavaScript 子集转译执行。

# 附录 A – 形式语法

以下是 Animac 语言（Scheme 模式）的完整 BNF 形式语法。`<表达式>` 各产生式的语义见[第 4 章](#4--表达式)，程序结构见[第 5 章](#5--程序结构)。

## A.1 – 词法结构

```
<程序>     ::= <顶层形式>*
<顶层形式> ::= <定义> | <语法定义> | <模块声明> | <表达式>

<标识符>   ::= 除定界符 ( ) [ ] { } " ` , 、空白字符和 ; 之外的任意字符序列，
               但不能构成 <数字>、<布尔>、#null、#undefined，也不是 <符号字面量>
<数字>     ::= [+-]?[0-9]+ | 含小数点或 e/E 指数部分的十进制数
<字符串>   ::= " <字符串元素>* "
<字符串元素> ::= 除 " 和 \ 之外的任意字符 | \" | \\ | \n | \t | \r
<布尔>     ::= #t | #f
<符号字面量> ::= '<标识符>
<关键字>   ::= lambda | define | set! | let | begin | return | ... | _ | if | and | or
             | cond | else | for | while | break | continue | case | do
             | quote | quasiquote | unquote | import | native
             | define-syntax | let-syntax | letrec-syntax | syntax-rules
```

## A.2 – 表达式

```
<表达式>   ::= <字面量> | <变量> | <特殊形式> | <过程调用>

<字面量>   ::= <数字> | <字符串> | <布尔> | #null | #undefined | <符号字面量> | <引用>
<变量>     ::= <标识符>           ; 含 <别名>.<标识符> 与 <库名>.<标识符> 形式

<引用>     ::= (quote <数据>) | '<数据>
<数据>     ::= <数字> | <字符串> | <布尔> | #null | #undefined | <符号> | (<数据>*)
<符号>     ::= <标识符>           ; 引用内的标识符按符号处理

<特殊形式> ::= <lambda> | <if> | <赋值> | <cond> | <begin> | <while>
             | <and> | <or> | <准引用> | <let-syntax> | <letrec-syntax>

<lambda>   ::= (lambda (<标识符>*) <体>)
<体>       ::= (<定义> | <语法定义> | <表达式>)+
<if>       ::= (if <表达式> <表达式> [<表达式>])
<赋值>     ::= (set! <变量> <表达式>)
<cond>     ::= (cond <子句>*)
<子句>     ::= (<表达式> <表达式>) | (else <表达式>)
<begin>    ::= (begin <表达式>*) | { <表达式>* }
<while>    ::= (while <表达式> <表达式>+)   ; 体内可出现裸符号 break / continue
<and>      ::= (and <表达式>*)
<or>       ::= (or <表达式>*)
<准引用>   ::= (quasiquote <准引用模板>) | `<准引用模板>
<准引用模板> ::= <数据>，其中可含 (unquote <表达式>) 与 ,<表达式> 与嵌套 <准引用>

<过程调用> ::= (<表达式> <表达式>*)
```

## A.3 – 定义、语法定义与模块声明

```
<定义>     ::= (define <变量> <表达式>)

<语法定义> ::= (define-syntax <标识符> <变换器>)
<变换器>   ::= (syntax-rules (<标识符>*) (<模式> <模板>)+)
<模式>     ::= <数据>，其中可含模式变量、_ 与 ...
<模板>     ::= <数据>，其中可含模式变量与 <子模板> ...
<let-syntax> ::= (let-syntax ((<标识符> <变换器>)*) <体>)
<letrec-syntax> ::= (letrec-syntax ((<标识符> <变换器>)*) <体>)

<模块声明> ::= (import <标识符> <字符串>) | (native <标识符>)
```

> 说明：源文件在解析前被包装为 `((lambda () <文件内容>))`，因此 `<顶层形式>` 事实上就是该隐式顶层 lambda 的 `<体>` 的元素；`import`/`native` 声明由解析器在整个语法树上统一收集，与出现位置无关。

# 附录 B – 示例程序

## B.1 – 尾递归阶乘

```scheme
(define fact
  (lambda (n)
    (define iter
      (lambda (k acc)
        (if (== k 0)
            acc
            (iter (- k 1) (* acc k)))))   ; 尾调用，不消耗栈
    (iter n 1)))

(display (fact 10))   ; ⇒ 3628800
(newline)
```

## B.2 – 父子进程与队列通信

```scheme
(native System)

(define q_to_child (System.make_queue 1))
(define q_to_parent (System.make_queue 1))

(define pid (System.fork))
(if (== 0 pid)
    { ; 子进程：读到 100 后回写 200
      (define rv (System.read q_to_child 2000))
      (display "child read=") (display rv) (newline)
      (System.write q_to_parent 200 2000)
    }
    { ; 父进程：写入 100 后等待回执
      (System.write q_to_child 100 2000)
      (define rp (System.read q_to_parent 2000))
      (display "parent read=") (display rp) (newline)
    })
; 输出 child read=100 与 parent read=200（先后次序不定）
```

## B.3 – 用卫生宏定义 let

Animac 没有 `let`，但可以用 `syntax-rules` 自己定义一个：

```scheme
(define-syntax mylet
  (syntax-rules ()
    ((mylet ((name val) ...) body1 body2 ...)
     ((lambda (name ...) body1 body2 ...) val ...))))

(mylet ((a "人类的本质") (b "是") (c "复读机"))
  (display a) (display b) (display c))
; 输出 人类的本质是复读机
```

# 附录 C – 已知限制

以下是当前实现已记录在案的限制与缺陷（详见仓库 `doc/ISSUES.md` 与 `doc/memo.md`），在程序中应当留意：

1. **`begin` 与 lambda 体的中间结果会残留在操作数栈上**（已知缺陷）。绝大多数程序不受影响（栈顶仍是最后一个表达式的值），但请勿编写依赖栈内容的行为；特别是在准引用模板中连续解除引用多个“函数体含多个表达式”的调用时，可能取到非预期的值。
2. **`while` 循环体不是独立的词法区域**：循环体内捕获的闭包共享同一个变量绑定；在循环中注册异步回调需手工封装一层 lambda（参见 `test/sleepsort.scm`）。
3. **宏不能跨模块导入/导出**；`letrec-syntax` 与 `let-syntax` 行为相同；模板中不宜使用本解释器不支持的 `let` 类语法。
4. **散列表的字符串键依赖字符串驻留机制**：键长不得超过 32 个字符；运行期构造的、不驻留的字符串副本不能可靠地用作键。
5. **REPL 是重放式的**：每次提交都会重放全部历史中的所有副作用（重新注册定时器、重新 fork、重新读盘等），会话代码应尽量幂等。
6. **错误消息不含行列号**（仅 JavaScript 转译器的错误带行列号）。
7. 内建变量 `write`、`read`、`fork` 已废弃；`blink.scm` 使用的 `(native File)` 库仅存在于早期 TypeScript 实现中，C 桌面宿主不可用。
8. 数值运算不做溢出检查；整数有效位数少于机器字长。
